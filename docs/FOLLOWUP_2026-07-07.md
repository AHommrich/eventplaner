## Step 4 — Restore drill documented and executed once

**Goal.** A repeatable drill that proves the mysqldump chain actually restores.

**Add a new section to `docs/RUNBOOK.md`** as §3.5 "Restore drill":

```markdown
### 3.5 Restore drill (semi-annual)

**Purpose.** A backup that has never been restored is not a backup. This
drill runs twice a year to prove the mysqldump chain works end-to-end.

**Cadence.** Q1 + Q3, in the maintainer's personal calendar. Every run
logged in §5 change log.

**Procedure (~30 min).**
1. SSH to the VPS, take a fresh dump:
   ```bash
   docker exec mariadb sh -c 'mysqldump -u root -p"$MYSQL_ROOT_PASSWORD" \
     --single-transaction --routines --triggers laravel' \
     > /root/restore-drill-$(date +%F).sql
   scp root@142.132.165.232:/root/restore-drill-*.sql ~/drill/
   ```
2. Locally, spin up an isolated MariaDB (NOT the dev container):
   ```bash
   docker run -d --name drill-db -e MYSQL_ROOT_PASSWORD=drill mariadb:11
   ```
3. Load the dump:
   ```bash
   docker exec -i drill-db sh -c 'exec mysql -u root -pdrill' \
     < ~/drill/restore-drill-*.sql
   ```
4. Sanity-check row counts against prod (users, guests, photos, drink_logs).
5. Tear down: `docker rm -f drill-db`.
6. Log outcome in §5 change log with date + row-count comparison.

**Object-Storage drill** (same cadence, separate).
Copy the latest snapshot prefix into a `drill-restore/` prefix, verify
one photo loads, delete the drill prefix afterwards.
```

**First execution.** When the maintainer is ready, run the drill once live to prove the runbook actually works. Record the outcome in §5 change log.

**Acceptance.** Runbook section exists, first drill logged in §5.

## Step 6 — Harden docker-compose merge safety

**Goal.** A manual merge mistake can no longer smuggle the dev `docker-compose.yml` onto staging or production.

**Changes.**

**6a) `.gitattributes`** — add:

Document the required per-clone one-off in `README.md`:

```bash

```

**6b) CI guard.** New workflow `.github/workflows/compose-guard.yml`:

```yaml
name: compose-guard

on:
  push:
    branches: [staging, production]

jobs:
  guard:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Ensure prod compose does not reference dev Dockerfile
        run: |
          if grep -qE '(artisan serve|dockerfile:\s*Dockerfile$)' docker-compose.yml; then
            echo "FATAL: docker-compose.yml points at dev Dockerfile" >&2
            exit 1
          fi
```

**6c) Update `README.md` "Deploy workflow" section** to point at the CI guard as safety net and describe the merge=ours setup.

**Acceptance.** A deliberate wrong merge on a test branch fails in `compose-guard`.
